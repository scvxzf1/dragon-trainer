# 授权分级：常备授权、事前批准、事后追认

本文约定"哪些动作 agent 可以直接做、哪些必须等用户"的判定规则，目的是让无人值守时也能推进，
同时不给不可逆操作开口子。判定依据是**可逆性与预算**，不是用户此刻在不在场。

配套阅读：`docs/proposal/multigpu_reference_validation_contract.md`（§V-1 的 50 次有效更新预算、
单次 `timeout 1200`、累计 ≤80 分钟，本身就是一份**一次性常备授权**）。

## 三档

| 档 | 判据 | 无人值守时 | 报告要求 |
|---|---|---|---|
| **A 常备授权** | 有界、可回滚、只写新路径、不动既有资产、有硬预算 | 直接做 | 必须写明消耗了多少预算（步数/时长/磁盘） |
| **B 事前批准** | 不可逆，或要覆盖既有资产，或要改契约，或要动用户在跑的任务 | 挂起不执行，列入待授权清单 | 给出完整申请：影响面、时长、观察方式、停止条件 |
| **C 事后追认** | 耗资源但完全可回滚 | 按 A 的预算做 | 注明已消耗预算，事后追认 |

## 本项目的具体归属

| 动作 | 档 | 附加条件 |
|---|---|---|
| 在**新建** run 根（`preprocess-<日期>-<哈希>/`）里重算缓存 | A | 源资产只读；不覆盖既有缓存；先单图 dry-run 报桶落点与实测体积 |
| 跑 §V-1 预算内的真实短训（RUN-A/B/C） | C | 计划已批准后不再逐次请示；累计 ≤50 次有效更新、单次 ≤1200s |
| 覆盖/删除既有 latent/TE 缓存、`post_image_dataset/`、训练历史与队列 | B | 一律事前批准 |
| 改 `CONSTANT_TOKEN_BUCKETS` 或其它契约表、改公开接口 | B | 一律事前批准 |
| `git push` 到线上、改 `main` | B | 一律事前批准，按 AGENTS.md「Git 推送和回滚」执行 |
| 启停用户正在跑的训练、下载模型、清空队列 | B | 一律事前批准 |

## 磁盘门：永远实时核对，不预授权

可用余量不足**预估占用的两倍**时：

- 自动不做，并说明缺多少；
- 不得自行清理、迁移或压缩既有资产来腾空间（那属于 B 档）。

## 不空等

申请授权后不允许整轮挂起：

1. 属于 A 档的，自行执行并在报告里注明预算消耗；
2. 不属于 A 档的，把该项挂起、写进「待授权清单」；
3. 继续推进不依赖该授权的工作；
4. 回合结束时统一给出清单，以及每项的完整申请文本（影响面、时长、观察与停止方式）。

## 失败与回滚

- A 档动作失败时只影响新建路径：删除该 run 根即可回滚，既有缓存零影响。
- 报告里必须写清"哪些契约仍未被验证"，不得用 A 档结果冒充 B 档决定的前置证据。
